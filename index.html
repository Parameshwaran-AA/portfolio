AI Infrastructure · LLM Serving

AgentServe — Agent-Aware LLM Serving GatewayLatest

Serving engines schedule one request at a time. An agent sends thirty for a single task, each containing the last one word for word, with tool calls in between that take anywhere from 300ms to two minutes. During a 45-second test run the session looks idle, so the GPU evicts its 40,000-token KV cache and recomputes it when the agent returns.

AgentServe makes the session the scheduling unit. Session-affinity routing sends follow-up calls back to the replica already holding the prefix, yielding to load rather than pinning. An online EWMA predictor learns per-tool return times, driving a three-tier cache policy that pins short pauses in HBM, offloads long ones to host DRAM, and drops dead sessions. Routing state lives in Redis so more than one gateway pod stays correct, and the Helm chart refuses to deploy multi-pod without it. Ships with an OpenAI-compatible API, SSE streaming, Prometheus/Grafana dashboards, and 135 tests across 6 CI jobs.

Benchmarked against stock vLLM on replayed coding-agent traces using a deterministic cost model. A harness to reproduce the result on real GPUs is in the repo.
